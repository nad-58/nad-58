## Repository maturity model

| Stage | Meaning |
|---|---|
| Foundation | README, scope, licence, and initial structure |
| Working | Runnable code or complete practical documentation |
| Quality-controlled | Tests, CI, issue templates, contribution guidance, and changelog |
| Mature | Versioned releases, wider examples, external contribution workflow, and stable API/docs |

The portfolio is moving from the working stage toward quality-controlled and mature repositories. The current priorities are consistent CI, contribution infrastructure, cross-repository navigation, and versioned releases.

## Confidentiality boundary

Public repositories use synthetic examples, generic templates, original diagrams, or publicly shareable research material. They exclude confidential client data, employer-specific proprietary content, patient data, regulated-device evidence, internal audit material, and restricted course resources.
